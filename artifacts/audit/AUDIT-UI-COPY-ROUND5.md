## 一、重要（2 条）

### 重要-1　引擎审计第 8 步的成本/打扰变成了负数，与主表相反（双重否定）

**位置**：`lib/simulation.ts:1265-1266` vs `components/sandbox-app.tsx:678`

```
引擎：cost: -weights.cost * (utility.cost - baselineMetrics.touchCost) * 100   ← 负系数
界面：cost:  costWeight  * (utility.cost - base.cost) * 100                     ← 正系数（你本轮改的）
```

上一轮 `Math.abs(...)` 把负值翻成正；本轮去掉 `Math.abs` 后没有同时翻系数，于是**又变回负值**。而 `lib/simulation.ts:1281` 的文案是

```
… = 风险改善 ${…avoidance} − 人力成本 ${…cost} − 打扰代价 ${…wake}
```

**后果**：当推荐策略**不是**「不主动沟通」时会出现双重否定。例如 50% 跌幅档推荐「分群差异化沟通」，第 8 步会渲染成：

```
= 风险改善 2.37 − 人力成本 -4.31 − 打扰代价 -1.62
```

读者按 `− (−4.31)` 读会得到加上去的结论。这与本轮要消除的符号问题性质相同，只是方向反了。

**为什么你测不出来**：10% 跌幅档的推荐恰好就是基线「不主动沟通」，两项差值恒为 0——正号负号都渲染成 `0.00`，符号错误被完全掩盖。**请在 50% 跌幅档（推荐分群沟通）复跑一次执行记录**，问题会立刻显形。

**建议**：把 `lib/simulation.ts:1265-1266` 的两个系数改成正值（与 `components/sandbox-app.tsx:678` 一致），并让两处共用同一个换算函数，避免今后再次分叉。

### 重要-2　服务端路径审计的「内容」列仍是旧术语

**位置**：`lib/harness/tools.ts` 的各工具 `audit` 文本

| 行号 | 残留词 | 本轮应改成 |

| 100、294 | 每步 | 每段 |
| 116、121 | 客群口径 | 客户筛选条件 |
| 143 | 原型、心理因素 | 客户画像、心理特征 |

其中行 232 的四个词正是本轮 A2/C 改名覆盖的对象，行 270 的 `Policy Gateway` 是 A4 点名必须清除的。

**影响**：你本轮把 `actor` 中文化了，但同一张卡右半边「内容」仍是旧词汇。用户从「智能任务中心」提交真实任务（服务端路径）后展开「执行记录」，会看到

```
群体推演   推演客户反应   10 个时间步、300 名客户，引擎耗时 113 毫秒；
                         推荐「分群差异化沟通」（避险收益 1.89、触达成本 0.435、唤醒 0.010）
合规审查   合规检查       5 项阻断、9 项待审批…；草稿级阻断已在模拟前由 Policy Gateway 强制执行…
```

左列已经是中文业务名，右列却回到 `避险收益 / Policy Gateway / 时间步`——比全英文更容易让人以为这些是内部指标。

**建议**：把 `lib/harness/tools.ts` 的 8 条 `audit` 文本按同一张术语表改写。这是本轮唯一没被覆盖的文案面，改完项目才算术语一致。
