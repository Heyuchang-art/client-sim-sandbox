## 一、重要（1 条）

### 重要-1　服务端任务路径的「执行记录」显示英文工具名，与本地路径不一致

**位置**：`lib/harness/runner.ts:275-283`

```js
audit.push({
  seq: step.index,
  actor: step.tool,        // ← 渲染为 scenario.extract / customers.query / …
  action: step.title,      // 中文
  result: runResult.audit, // 中文
  …
});
```

而本地路径的同一张卡取自 `lib/simulation.ts:1279-1281`，actor 已经是「任务规划／客户筛选／客户画像／关系网络／方案起草／群体推演／合规审查／结果复盘」。

**为什么没被发现**：`components/sandbox-app.tsx` 的 `AuditView` 用 `outcome?.audit?.length ? outcome.audit : result.audit` 选择数据源。你的 Playwright 导出走的是本地兜底路径（渲染文本里有「当前结果为本地计算，提交反馈前需先执行一次服务端任务」），所以看到的是 `simulation.ts` 那一份。

**影响**：客户经理从「智能任务中心」提交一个真实任务（服务端路径），展开「执行记录」会看到

```

customers.query    筛出目标客户   …

```

**建议**：给工具名加一张中文映射表（或直接复用 `defaultPlan()` 里的 `title`），把 `actor` 改成业务名；同时把 `step.tool` 放进审计条目的 `title` 悬停里，保留可追溯性。

## 二、建议改（1 条）

### 建议-1　主表的公式文字与符号约定有「双重否定」，严格按字面算不出来

**位置**：`components/sandbox-app.tsx:614`（描述）、`:614` 同行的数值单元格

**现状**：描述写「可以直接相减核对：综合推荐度 = 风险改善 − 人力成本 − 打扰代价」，而表格里 **人力成本列显示的是负值**：

```
统一风险提示    -2.48    1.89    -1.02    -3.35
```

严格按字面代入：1.89 − (−1.02) − (−3.35) = **+6.26**，与显示的 −2.48 不符。能算对的读法是「把负值当作扣分项、按绝对值相减」，也就是 1.89 − 1.02 − 3.35 = −2.48。

**为什么不算重要**：下一句「成本与打扰为负值是扣分项」已经把这个约定说清楚了，正常读者不会算错，而且**排序不会因此被误读**（不主动沟通仍是 0.00 最高），所以不影响决策——这与第二轮那个「朴素读法会得出相反结论」的硬伤不是一回事。

**另外审计轨迹用了相反的符号约定**：`lib/simulation.ts:1281` 对成本与打扰取了 `Math.abs(...)`，显示为正值，配「= 风险改善 − 人力成本 − 打扰代价」。同一组字段，主表是负值、执行记录是正值。

**建议**（二选一，2 处字符级改动）：
- ① 主表把成本与打扰改成正的**扣分幅度**（1.02、3.35），执行记录保持 `Math.abs`——两处统一为「正值 + 用减号」，公式字面成立；
- ② 或主表保持负值，把描述改成「综合推荐度 = 四项相加（成本与打扰已为负值）」。

**说明**：这一条我第三轮没有指出——当时我按你说的「1.89 − 1.02 − 3.35」验证了算术就放过了，没有注意到显示的数值本身带负号。是我的疏漏。
