## 二、改好了但引入新问题

### 新问题-1　「恐慌接近饱和导致边际收益收窄」的成因解释与实测相反

**位置**：`scripts/sweep-strategies.ts:167-168`、`artifacts/指标证据表.md:118`、docx 第 123 行（三处同一说法）

**原文**：「原因是高冲击下恐慌接近饱和、深度干预的边际收益收窄，而广覆盖的低成本仍占优。」

**实测复核（与边界用例完全同参数：λwake=8、6 小时、8 步、200 客户、高波动回撤客群）**：

```
跌幅 40%：broadcast  避险 0.1220  成本 0.1472  唤醒 0.01310  ->  净效用 0.00248
          segmented  避险 0.1289  成本 0.5108  唤醒 0.00788  ->  净效用 0.01478   ← 分群胜
跌幅 50%：broadcast  避险 0.1759  成本 0.1651  唤醒 0.00813  ->  净效用 0.09435   ← 统一提示胜
          segmented  避险 0.1955  成本 0.5567  唤醒 0.00635  ->  净效用 0.08903
```

两条反证：

1. **「边际收益收窄」不成立，实际是扩大。** 分群相对统一提示的避险收益差：40% 时 +0.0069，50% 时 +0.0196——**扩大约 2.8 倍**。分群输不是因为收益变小，而是因为成本罚分（λcost=0.1 下 0.0557 vs 0.0165）超过了它的收益优势。
2. **「恐慌接近饱和」不成立。** 同配置下峰值恐慌：不主动沟通 83.79%、分群 76.51%，而恐慌的 clamp 上限是 1.0（`lib/simulation.ts` 的 `clamp(value, 0, 1)`）。离饱和还差 16 个百分点以上，谈不上饱和。

**真实机制**：唤醒项按恐慌反向缩放——`lib/simulation.ts:853`

```
const wake = strategy.wake * (1 - priorPanic) * newlyReached;
```

恐慌越高，`(1 − priorPanic)` 越小，唤醒罚分自动衰减：统一提示的唤醒从 0.01310 掉到 0.00813（**−38%**）。而在 λwake=8 下，正是这个罚分撑着分群策略（它占了统一提示净效用的 96%）。罚分一衰减，分群的成本劣势（成本差 0.3636 → 0.3916，基本不变）就压不住了，于是 40%→50% 发生翻转。

**影响**：这是本轮最需要用实证纠正的一条——**披露本身是诚实的，但披露的内容是错的**。把「成因」写错比不写成因更危险：评委若照着这个解释追问「饱和点在哪」，会当场卡住。

**修复方向**：三处统一改为：

> 已知边界：把打扰权重取到极端值（8）且时长压到 6 小时时，40% 到 50% 区间会出现一次深度回落——推荐由分群差异化沟通回到统一风险提示。成因是唤醒罚分按 (1 − 恐慌) 反向缩放：市场冲击越高，恐慌越大，「打扰客户」的代价项越小，而深度干预的触达成本按触达量线性计费、不随恐慌衰减，于是高冲击下低成本广覆盖反而占优。该配置不属于默认口径，已记录为模型迭代项。

同时建议评估是否把唤醒项改为不随恐慌衰减的形式（例如只按触达量计），否则这条边界在更多配置下会复现。

**2. 「已知边界」的成因解释是否成立？**
