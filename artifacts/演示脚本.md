# 演示脚本（3 至 5 分钟）

本脚本用于初赛视频录制与决赛现场演示。主线是一个业务问题：客户经理要圈一批客户做活动，过去这件事要排队等数据团队排期，现在用一句话在几秒内拿到结果；拿到结果之后，还能直接把这批客户带进行为推演，看「如果这么做会怎样」。演示使用合成脱敏数据，全程不涉及任何真实客户信息。开始录制前请先执行 `npm run dev` 并确认左侧显示"系统运行正常"。

## 一、录制准备

- 启动开发服务器：`npm run dev`，访问 http://localhost:3000
- 浏览器窗口设为 1600 × 1000，隐藏书签栏与开发者工具
- 若配置了模型密钥，取数结果上方会显示"模型生成查询"；未配置时显示"规则生成查询"，讲解词按实际显示切换，不要念成模型生成
- 先点一次数据问答并提问一次，让服务端完成建表与数据装载，避免录制时首次请求的 1 秒装载出现在画面里

## 二、分镜脚本

### 第 1 段｜提出问题（0:00 至 0:30）

画面：停留在智能任务中心，鼠标停在左侧导航。

讲解词：

"券商客户经理每周都要取一次数。比如把总资产 500 万以上、近三个月有交易、还没配置过权益类产品的客户圈出来。这句话要变成一张名单，现在的流程是写需求单、提给数据团队、排队排期、再回头确认口径，通常以天计。我们做的事，是让这句话在几秒内变成结果，而且结果是怎么算出来的、有没有越过安全边界，全程可查。"

### 第 2 段｜一次取数走完五步链路（0:30 至 2:10）

操作：点击左侧"数据问答"，在输入框输入下面这句话，回车。

```
持有科技成长组合的高净值客户有多少人
```

讲解词（逐步指着执行链路的五个环节）：

"看这条链路。第一步理解意图，它把这句话识别成一次按客户数统计的查询。第二步检索元数据，它没有把九张表的所有字段一股脑塞给模型，而是按需取用——这次用到客户信息、持仓和产品三张表，以及客户数这一个已登记指标。第三步生成查询，这是实际执行的 SQL，注意它引用的是高净值客户这个客群标签。第四步安全围栏校验，三层都过了。第五步执行结果，19 名客户，端到端几毫秒。"

要点：讲"检索元数据"时强调按需取用，这是赛题攻关任务一的落点；讲第三步时可以点一下查询框，让评委看到 SQL 里没有臆造字段。

### 第 3 段｜安全围栏拦住幻觉与超范围提问（2:10 至 2:55）

操作：在输入框输入 `帮我看看大户`，回车；随后点击左侧"数据问答"上方的元数据徽标（或直接展示接口返回），弹出 9 张业务表 / 25 个指标 / 5 个工具。

讲解词：

"'大户'这个词在元数据里没有定义，系统没有猜一个数字给你，而是明确说不会，并建议换一种问法。宁可拒答也不答错，是这套系统的第一条原则。支撑它的是一套三层二十一条的规则：结构层挡住写操作、多语句、注释和没有行数上限的查询；语义层按表校验字段，像把持仓表的字段写到客户表上这种幻觉，会被直接拦下；结果层还会检查数值是否合理，比如客户数不可能超过全库客户数，多表连接之后直接 COUNT 出来的行数会被识破。挡不住的少数情况我们也不掩饰——能力边界语料 12 条现在全部正确拒答，靠的是一张域外词表——像「投诉」「满意度」这种九张表里根本没有的主题，直接拒答而不是兜底成一个客户总数。"

### 第 4 段｜从取数到推演（2:55 至 4:05）

操作：回到刚才的取数结果，点击"用这批客户跑一次推演"，页面切到群体行为沙盘。

讲解词：

"取数只回答了'有多少'，但业务人员真正要决策的是下一步：这 19 位客户要不要联系、用什么话术、会不会引发投诉。所以我们把取数结果直接接进了客户行为推演。这批客户在暴跌行情下会怎么反应，能按时间步看他们的恐慌、卖出倾向和流失风险；左边这批高净值客户如果统一推一条高波动产品的消息，红点会明显扩散，右侧的恐慌和卖出倾向同步抬升。换成人工深度更高、内容更个性化的方案，同样的客户群体反应就完全不同。"

要点：这一段用沙盘的三套方案对比，讲清"同一个客户群体，不同策略得到不同结果"，不要把沙盘讲成另一个产品。

### 第 5 段｜收尾（4:05 至 4:35）

画面：切到策略与审计页，鼠标滑过执行记录。

讲解词：

"最后说三个数字。第一，取数端到端在本地实测是 7 到 9 毫秒，赛题要求是分钟级。第二，安全围栏有二十四条绕过与误报场景的负例测试，加上规划器行为用例共五十条边界断言，全部通过。第三，每次取数和每次推演的工具调用、命中规则、时间戳都落进审计。需要如实说明的是，官方数据集要审核通过后才发放，现在跑的是我们自造的合成数据和自造问答对，准确率是自测结果，数据到位后我们会重跑评测脚本并更新材料。"

## 三、录制注意事项

- 每个分镜之间留 1 秒静止，方便后期剪辑
- 第 2 段与第 4 段是重点，合计不要超过两分半
- 不要说"准确率 100%"而不加限定语；必须带上"自造语料、自测结果"这层限定
- 若现场网络不稳定导致模型调用变慢，直接改成规则模式演示，讲解词改为"当前未接入模型，走确定性规划器"
