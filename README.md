# 证券客户营销取数智能体（ClientSim Ask）

面向券商客户经营团队的自然语言取数工作台，并在取数之后接一段客户行为推演。

**主场景（对齐赛题三「Agentic 智能问数在客户营销场景的应用」）**：业务人员用一句自然语言提问，智能体按需调用元数据工具、生成只读查询、经三层安全围栏校验后执行，返回结果表格与口径解释。取数链路真跑在九张业务表上，不是演示用的假数据。

**下游延伸**：取数结果页可以把这批客户直接带进群体行为沙盘，用确定性数值模型推演暴跌行情下的恐慌、卖出倾向、投诉与流失风险，回答取数之后的「如果这么做会怎样」。

## 九张业务表与数据规模

赛题给出的九张表已真实落库：客户信息、服务经理信息、产品信息、服务关系、公共维、客户持仓、客户资产、客户交易、客户资产流入流出。合成脱敏数据共 13622 行（客户 1000、服务经理 50、产品 20、服务关系 1319、持仓 2503、交易 5219、资金流水 2489），按固定种子确定性生成，可通过服务端接口幂等重建。

## 取数 Agent 的三条攻关任务

- **元数据（攻关任务一）**：登记九张表的表定义、25 个指标口径、11 条业务术语，并以 5 个工具（metadata.tables / metadata.describe / metadata.metrics / metadata.glossary / analytics.ask）的形式暴露给模型按需取用，而不是把全部元数据塞进提示词。建表语句、列名白名单与元数据定义同源。
- **安全围栏（攻关任务二）**：三层 20 条规则。结构层拦写操作、多语句、注释与无上限查询；语义层按表校验字段、核验指标是否登记；结果层检查行数列数与数值合理性（含「客户数不可能超过全库客户数」这一锚点）。拦截级问题直接拒绝执行并降级到确定性规划器，所有命中写入审计。
- **评测流程（攻关任务三）**：50 条标准问句 + 15 条留出问句 + 12 条能力边界问句，基准值由人工编写的对照查询在同一份数据上执行得到（不是拿实现里的常量当真值）。判定口径先行固定：数值按相对误差 ≤2%，分组按标签对齐后数值一致，边界集判定「是否明确拒答」。


## 能力边界

本项目把职责明确分成三类，这一点决定了系统能同时做到可复现与可审计。

**由大模型负责（可降级）**

- 自然语言业务目标的理解与任务规划
- 场景参数抽取（跌幅、持续时间、客户规模、时间步、随机种子），抽取结果必须通过 Schema 校验
- 候选沟通策略与话术的起草
- 结果解释与反思摘要

**由确定性数值引擎负责（不含模型调用）**

- 合成客户生成、五类原型与六项心理参数
- 三类关系网络与邻居情绪传播
- 逐时间步的个体行为演化，输出买入、持有、卖出、咨询、投诉、流失六类倾向
- 聚合指标、峰值暴露与干预优先级
- 同一场景与随机种子必然复现，输出聚合签名用于回归比对

**由合规硬边界负责（模型不可绕过）**

- 19 条合规规则的全文扫描与否定语境识别
- C1 至 C5 客户风险等级与产品风险等级的适当性矩阵
- 策略草稿在进入数值模拟**之前**先过 Policy Gateway：命中阻断级规则时强制改写为合规版本，并清除该策略的违规话术风险通道，因此合规拦截会真实改变模拟结果，而不只是改写一段展示文本
- 存量适当性风险（客户自身持仓超出其风险承受等级）按受影响客户数报告，随客户结构与随机种子变化
- 规则版本与模型版本分开记录

模型不可用时系统进入规则模式或确定性降级，界面会显式标注当前执行模式，不会把规则结果包装成模型结果。

## 沟通策略如何建模

三套策略（不主动沟通、统一风险提示、分群差异化沟通）由三个可调杠杆定义，其余引擎参数由杠杆推导，避免出现互相矛盾的独立常数：

| 杠杆 | 含义 |
| --- | --- |
| 触达覆盖率 | 事件窗口内最终能触达的客户比例 |
| 人工深度 | 0 为纯自动消息，1 为逐人人工沟通；决定人工作业的爬坡步数与单位成本 |
| 内容个性化 | 0 为通用话术，1 为逐人定制；决定通用话术对风险两端客户的失配程度 |

引擎据此推导：达到目标覆盖率所需步数、唤醒系数（主动触达引起的额外关注）与话术风险。安抚**只对被真正触达的客户生效**（逐客户门控），因此覆盖率是一个真实的输入，而不是展示用数字。

推荐顺序由效用在每个场景里算出来，不是常数写死的：

```
净效用 = 避险收益 − 触达成本 − 唤醒成本
避险收益 = 0.30×Δ恐慌峰值 + 0.30×Δ卖出 + 0.25×Δ流失 + 0.15×Δ投诉   （相对「不主动沟通」基线）
```

效用权重可由业务目标决定（更怕流失、更怕预算超支，还是更怕打扰客户）。需要如实说明：避险收益与触达成本量纲不同，把两者相加必然需要一个兑换率，而这个兑换率无法从合成数据里估计，只能由业务方设定。它是**业务参数**而非模型参数，因此界面上暴露实际取值并随结果留痕，结论只建立在与权重无关的结构性质上（跌幅越大、推荐方案的人工深度不下降）；夺冠配比会随权重变化，必须连同敏感性曲面一起看。

三套锚点只是「触达覆盖率 × 人工深度 × 内容个性化」空间里的三个点，引擎另外在该空间做 27 点网格搜索。搜索结果只按参数直接评估，尚未生成草稿文本、也未经 Policy Gateway 审查，因此不作为可执行推荐，界面会同时展示搜索最优与推荐锚点的净效用差异并说明原因。界面把这一节呈现为「还试过哪些组合」，默认折叠。

## 界面用词与本文档用词的对应

面向券商一线的用户界面采用业务语言，本文档与申报材料保留专业术语以便评委核对实现。两套用词指的是同一件事：

| 界面用词 | 本文档／材料用词 | 含义 |
| --- | --- | --- |
| 综合推荐度 | 净效用 | 排序依据，以「不主动沟通」为 0 分基准 |
| 风险改善 | 避险收益 | 相对不采取行动，客户恐慌／卖出／流失／投诉的改善量 |
| 人力成本 | 触达成本 | 触达所需的人力投入，按人工深度折算 |
| 打扰代价 | 唤醒成本 | 主动联系本身惊动平静客户的代价 |
| 推演段数（第 N 段） | 时间步 | 把持续时长切成若干段，逐段推演 |
| 结果指纹 | 聚合签名 | 用于判断两次运行是否完全一致 |
| 执行记录 | 审计轨迹 | 每一步的时间、内容与留痕 |

## 功能

- 智能任务中心：自然语言输入、真实 SSE 进度、结构化工具轨迹、执行概览、失败重试与取消。
- 客户洞察中心：按模拟期峰值暴露排序的高风险客户队列、六维性格雷达、个体行为时间轴、一人一策沟通建议与话术红线。
- 群体行为沙盘：三套锚点策略的结果对比、参数空间网格搜索的最优组合、五类原型分群布局的传播网络回放、逐时间步聚合指标与六类行为倾向分布。
- 策略与审计：策略比较（净效用 = 避险收益 − 触达成本 − 唤醒成本）、合规发现清单（含命中片段与字符区间）、执行审计轨迹（异步任务路径逐步记录真实时间戳）、报告导出。
- Skill 与审批：任务成功后自动沉淀候选技能与本次模拟指标快照；人工批准后的技能会在后续同类任务中被真实复用并留下事件与审计记录；同名技能版本号递增，可回滚到上一版本；无审批在线学习关闭。
- 人工反馈：评分与备注，仅用于生成候选技能，不自动修改引擎参数。

## 技术结构

- 前端：React 19、TypeScript、Tailwind CSS、shadcn/ui、Recharts
- 服务端：Vinext API Routes，部署于 Cloudflare Workers
- 数据：Cloudflare D1 / SQLite 兼容结构，表结构用 Drizzle 定义
- 模拟：浏览器与服务端共用的确定性 TypeScript 数值引擎

## 本地运行

```bash
npm install
npm run dev
```

访问 http://localhost:3000，首次启动会自动创建本地数据表。

模型接入为 OpenAI 兼容接口，在 `.env.local` 中配置。未配置时系统进入规则模式，功能完整可用。

```
OPENAI_BASE_URL=
OPENAI_API_KEY=
OPENAI_MODEL=
MODEL_TIMEOUT_MS=20000
MODEL_MAX_RETRIES=1
```

密钥不进入代码仓库；部署环境使用平台密钥管理。

## 场景配置契约

自然语言任务会被解析并校验为结构化场景：

```json
{
  "marketShock": -0.10,
  "durationHours": 24,
  "customerCount": 300,
  "timeSteps": 10,
  "seed": 20260830,
  "targetSegment": "high_volatility_drawdown"
}
```

- 取值范围：跌幅 0.01 至 0.5、时长 1 至 168 小时、客户 50 至 1000、时间步 5 至 20。
- 抽取失败或缺失的字段使用显式默认值，并在界面提示 `defaultedFields`，不静默忽略用户输入。
- `targetSegment` 为真实筛选条件：高波动回撤客群要求持有高波动产品，且在 10% 基准冲击下持仓弹性 beta ≥ 0.8（等价于回撤主项不低于 8%，不含客户个体 ±1.5 个百分点的扰动，因此入选客户的期末回撤可能略低于 8%）；命中不足时按回撤降序补足并在界面与审计中标注；`all_customers` 为对照组。
- 场景配置、模型版本、规则版本与随机种子写入审计轨迹与导出报告。

## 数据与合规声明

- 当前全部客户为合成且脱敏的演示数据，不包含任何真实客户信息，不宣称真实客户行为的预测准确率；指标用于说明系统行为的一致性与稳定性。
- 系统只输出分析、建议与模拟结果，不自动触达真实客户，不执行任何交易或产品申购动作；高风险动作必须经过人工审批。
- 不保存也不展示模型的原始思维链，界面只呈现因素权重、数据证据、规则命中与结构化执行轨迹。
- 无审批的在线学习处于关闭状态；人工反馈只用于生成候选技能，不会自动修改引擎参数或策略权重。
- 同一结构化场景与随机种子完全复现；调整市场跌幅会真实改变客户初始冲击、情绪传播、卖出与流失风险，而不只是改变界面文字。
